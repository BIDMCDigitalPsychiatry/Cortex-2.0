# Open questions and brief-vs-repo conflicts

The feature-expansion brief says that where it conflicts with the repository, the
repository's existing design documents win; each conflict is written down here with the
resolution that was implemented. Items are flagged in the PR description.

| # | Topic | Conflict | Implemented resolution | Status |
|---|---|---|---|---|
| 1 | Protected branch | Brief says "do not push to `main`"; the repository's default branch is `master` (there is no `main`). | `master` treated as protected; work on `feature/cortex2-feature-expansion`, draft PR into `master`. | resolved |
| 2 | Baseline not green | Brief: "`pytest -q` is green at HEAD (161 test functions)". 161 is correct, but under pandas 3.1 10 of 165 collected tests failed, and ruff 0.17 reported 68 findings. | Phase 0 fixes the datetime-resolution bug and the lint findings (see CHANGELOG, Phase 0). | resolved |
| 3 | Same bug in a workflow | `workflows/build_episode_ios_sensorkit_evidence.py` also converts with `dt.astype("int64") / 1e6`. | Not changed: library code must not depend on `workflows/`, and the study scripts are out of scope. The owner should switch it to `datetime_to_epoch_ms`. | open |
| 4 | Contact hashing | Brief: "salted-sha256 approach used in `_nearby_identifier_hash`". That function uses **blake2b (16-byte digest)** over `study_id\|source_platform\|type\|address`, unsalted apart from the study id. | Repo wins: one shared `_pseudonymous_hash(kind, value)` (the existing blake2b scheme). Nearby-device tokens are unchanged. If a secret salt is wanted, add it once to `_pseudonymous_hash`; that changes every token, so it needs a re-run. | resolved, decision for owner |
| 5 | Device OS | Brief: telephony `source_absent` "when the episode platform is iOS". Episodes carry `source_platform` (= "mindlamp"), not the OS. | Optional `device_os` on the episodes schema and a `device_os=` keyword on features. `source_absent` only when `device_os == "ios"`. An unknown OS with no records gives `no_raw_data`. Populating `device_os` (e.g. from `workflows/build_lamp_analytics_episode_os.py`) is a study step. | resolved |
| 6 | Battery | Brief: add `battery.yaml` or ride on screen. | Ride on `screen.battery_level_fraction`; no battery schema. | resolved |
| 7 | New-stream export columns | No real mindLAMP exports for telephony/survey/cognitive/steps/sleep were available. | Accepted column names (documented per adapter method) follow mindLAMP field names: `call_type`/`sms_type`, `call_duration` in seconds, `call_trace`/`sms_trace`, activity `temporal_slices` as `question`/`value`/`duration`, HealthKit sleep codes. **Confirm against a real export.** | open |
| 8 | `unknown` category | Brief lists `direction` ∈ {incoming, outgoing, missed} and `representation` ∈ {in_bed, in_sleep, in_awake}. | `unknown` is also allowed, matching the existing screen schema (`allowed_events` includes `unknown`), so one unmapped code does not abort a whole file. Features ignore `unknown` rows and count them. | resolved |
| 9 | Status vocabulary | GPS design doc §8 lists `observed_value` / `extraction_failure` / `masked`; the existing `FeatureStatus` enum and the brief use `observed` / `extraction_failed` / `analysis_masked`. | The enum is the code contract, and the doc calls its list "initial". Adopt the enum values; §8 now points to `status_vocabulary.md`. `feature_empty` kept as deprecated, never emitted. | resolved |
| 10 | Mobility zeros | `compute_daily_mobility_features` returned `0.0` distance with no supported time, and `0.0` implausible fraction with no candidates. Rule 2 forbids both. | Now NaN with `insufficient_observability` / `not_applicable`. **Downstream effect:** `workflows/build_gps_clinical_weekly_features.py` takes weekly mean/median of daily distance (NaN-skipping). Days with GPS rows but no supported time used to enter as 0 m and are now excluded, so re-running that workflow will change (raise) those weekly summaries. The workflow already used NaN for days with no rows; this makes the two cases consistent. | resolved, re-run needed |
| 11 | Phase 2 module list | The brief lists `gps_location_episodes.py` and `gps_anchor_episodes.py` among the modules with literal status strings. | They emit only edge-level `spatial_status`, which is a separate vocabulary. No change. `gps_observability.py` did emit literals and was converted. | resolved |
| 12 | Missing design specs | The brief cites "the design document" for the Van Someren IS/IV formulas, the Borger sleep method and the six-class missingness label. The repo's design doc is GPS-only and contains none of them. | Each spec is written into `docs/features/{accelerometer,sleep,missingness}.md` and implemented against it. Review those pages as the design of record. | resolved, review requested |
| 13 | van Hees non-wear rule | The paper's wording reads "SD < 13 mg **or** range < 50 mg (2 of 3 axes)"; GGIR requires both per axis. | GGIR form (AND), which is more conservative. Plus the phone adaptation: unobserved ≠ non-wear, and non-wear is the union of still windows rather than GGIR's centre-block labelling. | resolved |
| 14 | IS with never-observed clock hours | The Van Someren formula assumes all 24 clock hours are present. | `p` = number of clock hours observed on ≥ 1 valid day; IV counts only consecutive observed pairs. With complete data both reduce to the published formulas (tested). | resolved |
| 15 | Home definition | Legacy `hometime` uses the day's top-ranked significant location; the GPS design doc (§4) requires an episode-level latent home. | Episode-level night-majority home (`gps_home`); the legacy `hometime` registry entry is left as the `cortex` engine feature. | resolved |
| 16 | Activity-space zero floor | Brief: `observed_zero` "below squared median accuracy". Noise with SD near the accuracy radius produces a hull larger than accuracy². | Implemented as specified (`area ≤ accuracy²`). Limitation documented in `docs/features/gps.md`; consider π·accuracy² after looking at real still days. | open |
| 17 | Circadian movement scale | Saeb et al. 2015 report raw least-squares spectral energy in degrees², which grows with distance travelled. | Normalised power (share of variance explained) on projected metres, so the value measures periodicity rather than range. `log(E_east + E_north)` as in the paper. Values are not numerically comparable with Saeb's. | resolved, review requested |
| 18 | Zero communication | Brief: daily counts, `source_absent` on iOS. On Android a day with no telephony rows is ambiguous (no calls vs. logger stopped). | `observed_zero` only with evidence the logger ran (`stream_active_in_episode` and ≥ 12 h `source_observed_ms`, e.g. screen-supported time); otherwise `no_raw_data`. The driver (Phase 9) supplies both. | resolved |
| 19 | Survey missing-item rule | Brief gives no rule; PHQ-9/GAD-7 publications do not define one. | `min_items`: PHQ-9 ≥ 7/9, GAD-7 ≥ 5/7, no pro-rating (matches the BIDMC pipeline convention). Editable in the YAML spec. | resolved, decision for owner |
| 20 | Ex-Gaussian τ at non-positive skew | Method of moments gives τ ≤ 0 when skewness ≤ 0. | `not_applicable` (the model does not fit) rather than 0, per rule 2. | resolved |
| 21 | Completeness weight formula | Brief gives the signature `(coverage_fraction, longest_gap_ms, n_missing_runs, n_bins, *, alpha, beta)` but no formula. | `coverage^α × (1 − longest_gap/(n_bins × bin_size_ms))^β`; `n_missing_runs` used only as a consistency check. Functions that only know an observed total use the one-gap lower bound. | resolved, review requested |
| 22 | Phenotype thresholds | Six-class label thresholds (10 % complete, 60 % dominance, battery ≤ 0.15, ≥ 12 eligible hours) are not in any design doc. | Implemented as keyword parameters with these defaults; calibrate on the BIDMC hourly table before using the label in a paper. | open |
